# Read → Books: уточнённый план

Готов код двух этапов: локальный конвертер EPUB → JSON v2 и вывод этого формата
непосредственно в Books с экранными страницами и свайпами. Пользователь проверил
конвертер и прислал The Woman in the Dunes (61 137 слов, около 3,4 МиБ).
По присланному фрагменту менять схему не понадобилось. Тесты и браузерные проверки
агент по просьбе пользователя не запускает; новая читалка пока им не проверялась.

Следующий шаг: пользователь публикует фронтенд и загружает JSON в существующий
Storage, обновив bookId в каталоге. Дополнительно Worker переведён на общие
`SUPABASE_BUCKET=Umbrello` и `ALLOWED_USER_IDS`: нужно переименовать прежние
переменные и опубликовать обновлённый Worker по [WORKER.md](WORKER.md).
Общий экран входа и уведомления об отказе в бот добавлены; для них публикуются
Worker и обновлённый фронтенд. Дальше — сохранение места и definitions.
Отмеченные ниже пункты означают наличие
кода, а не прохождение проверки на телефоне.

## Цель и ограничения

Мобильная читалка в Telegram Mini App: страницы по размеру доступного экрана
без вертикальной прокрутки, перелистывание свайпами, попап с definition
по нажатию на слово и автоматическое сохранение на телефоне.

- Сайт остаётся статическим и публикуется на GitHub Pages.
- Существующий Cloudflare Worker оставляем: доступ к приватным книгам и запросы к ИИ.
  Пользователь подтвердил этот вариант.
- Текущий способ подготовки EPUB и хранения книг в Supabase сохраняем.
- Прогресс и полученные definitions храним на устройстве отдельно для каждого читателя.
- Адаптацию для компьютера в эту работу не включаем.

Основной сценарий:

> Открыть книгу на сохранённом месте → читать и листать свайпами → нажать слово →
> увидеть definition в попапе → закрыть попап и читать дальше.

## 1. Минимальная читалка и свайпы

- [x] Оставить простой выбор книги; в самой читалке показывать текст без оглавления
  и дополнительных панелей настройки.
- [x] Рассчитывать страницы на телефоне по реальной ширине и доступной высоте
  области чтения после загрузки шрифтов. Фиксированные 300 слов не использовать.
- [x] Учитывать интерфейс Telegram и безопасные отступы экрана; текст каждой
  страницы должен целиком помещаться без обрезанных строк и вертикальной прокрутки.
- [x] Перелистывать книгу горизонтальными свайпами: влево — дальше, вправо — назад.
- [x] Различать свайп и нажатие на слово; свайп не должен
  случайно открывать попап.
- [ ] Пока попап открыт, блокировать жесты текста под ним.
- [ ] Закрывать попап крестиком или нажатием на затемнённый фон. Telegram Back
  сначала закрывает попап; при закрытом попапе возвращает из книги в библиотеку.
- [ ] Не перестраивать страницу и не менять её позицию при открытии и закрытии попапа.
- [x] При устойчивом изменении размеров области чтения пересчитывать страницы,
  сохраняя текущую позицию в тексте. Не пересчитывать на каждом кадре жеста Telegram.
- [x] Разрешить предложению продолжаться на следующей странице; полное исходное
  предложение хранить в загруженных данных. Передача его в ИИ — на этапе definitions.

Разметка выполняется браузером через CSS-колонки высотой в экран. В DOM только
текущая глава; границы страниц определяются по фактической разметке текста.
Поворот экрана сохраняет адрес видимого текста, а не номер страницы.
Проверку в мобильном WebView выполняет пользователь. Границы глав, абзацы
и ID предложений сохраняются в исходной структуре.

## 2. Автоматическое сохранение позиции

- [ ] Сохранять начало текущей экранной страницы для пары «читатель + книга».
- [ ] При повторном открытии автоматически продолжать с сохранённого места.
- [ ] Записывать изменения по ходу чтения; не полагаться только на событие закрытия Mini App.
- [ ] При принятии расширенного формата из раздела 6.1 привязывать место к ID
  первого видимого слова и позиции внутри него при необходимости. ID слова
  однозначно связывается с предложением; для границ без слов доступен адрес предложения.
  После изменения размеров экрана открывать страницу, содержащую сохранённое место;
  номер страницы и координаты в пикселях не использовать как основной адрес.
- [ ] Ошибка хранения не должна мешать читать; показывать короткое сообщение,
  если приложение не смогло сохранить данные.

Отдельные кнопки «Продолжить», проценты, статусы книги, ручные закладки,
история и серверная синхронизация в этот план не входят.

## 3. Definition по нажатию на слово

- [ ] При нажатии сразу открывать модальный попап поверх книги.
- [ ] Сначала искать сохранённый ответ для этого слова у текущего читателя в этой книге.
- [ ] Если ответа нет, передавать через Worker всё предложение и точную позицию
  нажатого слова. Позиция нужна, если слово встречается в предложении несколько раз.
- [ ] Брать предложение, ID и диапазон слова из подготовленного файла;
  повторно разбивать текст на предложения и слова на телефоне не требуется.
- [ ] Просить ИИ определить значение слова в этом контексте. Если оно входит во
  фразовый глагол или устойчивое выражение, вернуть definition всего выражения.
- [ ] Показывать в попапе определяемое слово/выражение и краткий definition.
  Рабочее допущение: definition на английском, без перевода на другой язык.
- [ ] Автоматически сохранять успешный ответ; отдельного действия «Сохранить» нет.
- [ ] Показать состояние загрузки и ошибку с возможностью повторить запрос.
- [ ] Объединять повторные нажатия во время одного запроса, чтобы не отправлять дубликаты.
- [ ] Если попап закрыли до ответа, можно сохранить успешный результат, но нельзя
  снова открыть попап или подменить содержимое другого открытого попапа.

Выделение нескольких слов, перевод предложения, дополнительные пояснения
значения и употребления, озвучивание не нужны.

Worker проверяет Telegram-подпись и доступ к Books. Ключ ИИ остаётся в Worker.
В запрос попадает предложение с указанием нажатого слова, а не вся книга.
Ответ имеет ограниченный формат и выводится как текст.

## 4. Подчёркивание и повторное использование ответа

- [ ] После успешного ответа подчёркивать это слово во всех местах текущей книги.
- [ ] При открытии других страниц и после перезапуска восстанавливать подчёркивания.
- [ ] Нажатие на подчёркнутое слово открывает сохранённый попап без запроса к ИИ.
- [ ] Использовать один сохранённый ответ на слово в рамках книги, даже если в другом
  предложении смысл отличается. Пользователь явно подтвердил это упрощение.
- [ ] Для поиска совпадений не учитывать регистр и окружающую пунктуацию;
  разные формы слова автоматически не объединять.
- [ ] Если ИИ определил фразовый глагол, сохранять ответ под нажатым словом вместе
  с полным названием выражения. Другие вхождения этого слова показывают тот же ответ.
- [ ] Ошибки запроса не сохранять как definitions и не подчёркивать слово до успеха.
- [ ] Добавить в попап сохранённого ответа действие «Удалить definition».
- [ ] При удалении очистить ответ из памяти и локального хранилища, снять
  подчёркивания со всех вхождений этого слова в книге и закрыть попап.
- [ ] Следующее нажатие на это слово отправляет новый запрос с контекстом того
  предложения, на которое нажал читатель. Само удаление не вызывает запрос к ИИ.
- [ ] Запоздалый ответ старого запроса не должен восстанавливать удалённую запись.

Например, если первый ответ для «give» был о «give up», другие вхождения «give»
в этой книге покажут тот же сохранённый definition. Новый анализ контекста
возможен после явного удаления ответа и следующего нажатия на слово.

Кэш ограничен текущей книгой. Отдельный словарь, список слов, редактирование,
учебные карточки и повторение не нужны.

## 5. Где хранить данные

Предложение: Telegram DeviceStorage как основное хранилище в поддерживаемых
клиентах Telegram; localStorage как запасной вариант для клиентов без этого API.
Оба варианта доступны из JavaScript статического сайта на GitHub Pages.

DeviceStorage — локальное хранилище Telegram с лимитом 5 МБ на пользователя
для одного бота, доступное с Bot API 9.0. Оно подходит для небольшой позиции
чтения и коротких definitions; файлы книг туда не сохраняем.

- [ ] Сделать единый слой чтения и записи данных с проверкой поддержки API.
- [ ] Разделять данные по приложению, Telegram ID читателя, книге и версии формата.
- [ ] Для localStorage обязательно включать Telegram ID в ключи: оно разделяется
  по origin сайта, а не автоматически по Telegram-аккаунтам.
- [ ] Telegram ID для разделения брать из проверенного Worker аккаунта;
  выбранное имя профиля не определяет владельца данных.
- [ ] Сохранять прогресс и definitions раздельно; не перезаписывать весь кэш
  при каждом перелистывании.
- [ ] Проверить предел объёма и ошибки записи; не удалять старые definitions
  автоматически, поскольку это приведёт к повторным платным запросам.
- [ ] Предусмотреть перенос локальных данных при переходе с запасного хранилища
  на DeviceStorage после обновления клиента, без потери имеющихся записей.

Данные остаются на конкретном устройстве. Автоматической синхронизации между
телефонами нет. После удаления локальных данных восстановление не гарантируется.
localStorage сохраняет данные между обычными сессиями, но зависит от настроек
и очистки хранилища браузера/WebView.

## 6. Подготовка и добавление книги

Подготовка структуры книги выполняется локально один раз. Разметка экранных
страниц выполняется на телефоне при чтении.

1. Владелец открывает `tools/book-preparer.html` на компьютере и выбирает EPUB.
2. Конвертер извлекает текст, главы и абзацы, разбивает текст на предложения
   и слова, присваивает ID и готовит связи между ними. Результат можно скачать
   целиком или скопировать один абзац для обсуждения. Предпросмотр книги пока не делаем.
3. Владелец проверяет результат и загружает `book.json` в приватный Supabase Storage,
   затем добавляет запись в `books/index.json`. EPUB и preview на сайт не публикуются.
4. Mini App получает каталог и подготовленный JSON через существующий Worker.
5. Читалка раскладывает структурированный текст по доступному экрану конкретного
   телефона и открывает сохранённое место.

- [x] Обновить читалку так, чтобы готовый массив `pages` в старом JSON не определял
  границы экранных страниц. Источник текста — главы, абзацы и предложения.
- [x] Для перехода на экранную разметку использовать уже извлечённые главы,
  абзацы и предложения. Старое поле `pages` больше не определяет отображение.
- [x] Для расширенного формата выполнить локальное дополнение имеющегося JSON
  метаданными слов либо повторную подготовку EPUB. Не переносить эту работу на телефон.
- [x] Обновить документацию: число страниц из старого конвертера не выдаётся
  за число экранных страниц Mini App. Отдельного preview для формата 2 нет.

Загрузка и разбор исходного EPUB на телефоне в этот план не входят. При добавлении
новой книги обновляются файлы Storage и каталог; перепубликовывать сайт не требуется.

### 6.1. Предложение: максимум подготовки на компьютере

Базовый пакет реализован в HTML-конвертере как формат 2; точная схема описана
в `tools/README.md`. Цель — готовый пакет текста и связей, чтобы мобильная страница
отвечала за отображение, жесты, локальные данные и запросы. Окончательный формат
уточним после пользовательской проверки.

**Два разных идентификатора слова:**

- `wordId` (`word.id` в JSON) — уникальное вхождение: `w1`, `w2`, … по всей книге.
  Два одинаковых слова в одном предложении имеют разные ID; связь задаёт вложенность.
- `wordKey` (`word.key` в JSON) — нормализованное написание для общего definition: например, `gave`.
  Регистр и окружающая пунктуация не учитываются. Формы `give`, `gave`, `given`
  остаются разными ключами согласно текущему правилу.

Прогресс хранит `wordId`. Definition хранится по сочетанию «читатель + книга +
wordKey». Поэтому все вхождения слова подчёркиваются и очищаются вместе,
а контекст запроса относится к точно выбранному вхождению.

**Что подготовить локально:**

- [ ] Текст предложений с сохранёнными пробелами и пунктуацией после согласованной
  очистки EPUB. Заголовки и абзацы уже представлены отдельными блоками.
- [ ] Список слов каждого предложения: ID вхождения, общий ключ, начало и конец
  в исходном предложении. Зафиксировать единицы смещения, совместимые с JavaScript
  (UTF-16), и проверить символы вне BMP, апострофы и дефисы.
- [ ] Связи «слово → предложение → абзац → глава» и последовательный порядок текста.
  Вложенные ID и структура JSON могут выражать связь без повторения текста.
- [ ] Таблицу уникальных `wordKey` для книги. Полный список всех вхождений по ключу
  добавлять только при реальной необходимости: общая метка у слов уже позволяет
  подсветить отрисованную часть и восстановить подсветку на следующих страницах.
- [ ] Версию формата и правил токенизации. ID гарантировать для одной версии
  подготовленного текста; не обещать их неизменность после редактирования книги.
- [ ] Проверку уникальности ID, диапазонов слов и полного восстановления текста,
  чтобы разметка не удаляла знаки препинания и не склеивала слова.
- [ ] Проверку размера выходного файла с учётом существующего лимита Worker 8 МиБ.
  Полное предложение хранить один раз; слова ссылаются на него через структуру
  и диапазоны, без отдельной копии контекста для каждого вхождения.
- [x] Выбор абзаца и копирование фрагмента JSON с предложениями, словами и диапазонами.
  Предпросмотр книги отложен по уточнению пользователя.

Используется `formatVersion: 2`, с полями `words[].id`, `key`, `start`, `end`.
При добавлении метаданных слов без изменения исходной структуры
предложений сохранить идентичность подготовленного текста (`bookId`), чтобы
не сбрасывать связанные данные только из-за новой технической разметки.

**Что останется на телефоне:**

1. Загрузить подготовленный пакет и создать текстовые элементы по готовым диапазонам.
2. Разложить текст на экранные страницы по фактическому размеру области чтения.
3. Обрабатывать свайпы и нажатия по `wordId`.
4. По `wordKey` открыть сохранённый definition либо отправить подготовленный контекст в Worker.
5. Сохранить или удалить ответ, обновить подчёркивания и записать позицию чтения.

Физические границы экранных страниц заранее универсально не вычисляются:
они зависят от телефона, доступной области Telegram и фактической отрисовки шрифта.
Определение значения и распознавание фразового глагола остаются задачей ИИ при
первом запросе читателя. Новых языковых функций это расширение формата не добавляет.

## Порядок реализации

1. Готов инструмент EPUB → JSON; пользователь проверил и прислал книгу.
2. Присланный фрагмент подходит; изменение формата не понадобилось.
3. Готов код вывода непосредственно в Books: страницы по экрану и свайпы.
4. Подключить хранение, восстановление позиции и модальный попап в том же приложении.
5. Добавить definition через существующий Worker без отдельного режима локальной авторизации.
6. Подключить сохранение и удаление ответов, подчёркивания по всей книге
   и повторное открытие из кэша.
7. Пользователь проверяет на телефоне в Telegram после публикации на GitHub Pages.

Отдельную локальную читалку и последующий перенос её логики в Telegram не делаем.
После каждого этапа кратко сообщать в чате, что сделано и что осталось.
Тесты и браузерные проверки агент не запускает: пользователь проверяет сам.

## Проверка готовности

- После закрытия и повторного открытия Mini App сохраняется место чтения.
- Разные Telegram-аккаунты не смешивают прогресс и definitions.
- Каждая страница помещается в доступную область телефона без вертикальной
  прокрутки и обрезания текста; горизонтальный свайп листает страницы.
- На границах страниц текст не теряется и не дублируется. Длинные абзацы
  и предложения могут продолжаться на следующем экране.
- Изменение размеров Mini App и поворот телефона сохраняют текущую позицию в тексте.
- Открытый попап блокирует жесты книги; его закрытие не меняет позицию текста.
- Первый клик отправляет предложение и положение слова; успешный ответ сохраняется.
- Два одинаковых слова в одном предложении различаются по ID, при этом используют
  один общий ключ definition. Текст с апострофами и необычными Unicode-символами
  не меняется при подготовке и отображении.
- Повторный клик на это слово в другом месте книги и после перезапуска не вызывает ИИ.
- Удаление definition снимает все подчёркивания этого слова в книге и сохраняется
  после перезапуска; следующий клик делает новый запрос с новым контекстом.
- Фразовый глагол определяется ИИ по контексту без ручного выделения выражения.
- Для предложения на двух экранных страницах ИИ получает исходное предложение целиком.
- Ошибки сети, запоздалые ответы и ошибки локального хранения обработаны.
- Подчёркивания не меняют размеры текста и не сдвигают чтение.
- Learn words и существующий доступ к приватным книгам продолжают работать.
