# Books: подготовка, хранение и чтение книг

**Read** состоит из двух вкладок:

- **Learn words** — прежнее чтение из `users/<id>/read.json` со словарём и тестом.
- **Books** — библиотека и простая читалка готовых книг.

Книги и каталог хранятся в приватном Supabase Storage и приходят только через
Cloudflare Worker. Worker проверяет подпись Telegram `initData` и пускает лишь
аккаунты из общего `ALLOWED_USER_IDS`. Выбранный профиль (`?user=me`) — только
подпись в интерфейсе, а не авторизация. Единые настройки приложения описаны
в [WORKER.md](WORKER.md).

```text
GitHub Pages: books.html + JS/CSS, без текста книг
    │ POST + Telegram initData
    ▼
Cloudflare Worker: подпись Telegram → ALLOWED_USER_IDS
    └─ читает books/index.json и книги из каталога в приватном Storage
```

Позиция чтения, история, словарь и загрузка EPUB через интерфейс пока не
предусмотрены. Книга целиком загружается при открытии и живёт только в памяти
страницы.

## 1. Подготовить книгу

Основной инструмент — `tools/book-preparer.html`: открой на компьютере, выбери
EPUB и скачай JSON. Сервер и Python для него не нужны. Он готовит формат 2:
главы → абзацы → предложения → слова с ID, общим ключом и UTF-16 диапазонами.
Схема и порядок работы — [tools/README.md](../tools/README.md).

Книга может содержать copyright, печатное содержание и рекламу других изданий:
конвертер сохраняет такие текстовые разделы из EPUB. Отдельного меню содержания
в читалке нет. Просмотри список разделов и скопированные фрагменты в конвертере.

Готовый файл храни в `output/` (исключён из Git) и загружай в приватный Storage.
Не добавляй JSON с текстом книги в публичный репозиторий.

### Прежний Python-конвертер (формат 1)

Зависимости конвертера описаны в `tools/pyproject.toml` и `tools/uv.lock`
(Python 3.14). Нужен установленный [uv](https://docs.astral.sh/uv/).
Команды выполняются из корня репозитория; `uv run` сам создаёт `tools/.venv`
и ставит зафиксированные версии.

```sh
uv run --project tools tools/prepare-book.py "path/to/My Book.epub" --output output/my-book
```

В `output/my-book/` появятся:

- `book.json` — то, что загружается в Storage;
- `preview.html` — локальная проверка разбиения, открывается двойным кликом.
  В Storage его не загружают.

Конвертер печатает `bookId` — он понадобится для каталога. Необязательный
`--words 250` меняет размер страницы (по умолчанию около 300 слов).
`output/` и `*.epub` исключены из Git: текст книг не должен попасть в репозиторий
или на GitHub Pages.

Проверка конвертера:

```sh
uv run --project tools python -m unittest tests/prepare_book_test.py
```

### Что делает конвертер

- Берёт название и автора из метаданных, текст — в порядке spine.
- Удаляет скрипты, стили, изображения, навигацию и номера страниц печатного
  издания. Текст не переписывается: только пробелы HTML схлопываются в один.
- Главы определяются по заголовкам: уровень, который встречается в книге
  хотя бы дважды (например `<h2>`). Более мелкие заголовки остаются внутри главы
  с `"kind": "heading"`. Файл без заголовков начинает главу, только если он есть
  в оглавлении EPUB; иначе продолжает предыдущую.
- Предложения режет pysbd с учётом сокращений (Mr., e.g., U.S.) и диалогов.
- Страницы ~300 слов, предложения не разрываются, каждая глава с новой страницы.

### Формат book.json

```json
{
  "formatVersion": 1,
  "bookId": "<SHA-256 подготовленного текста, 64 hex-символа>",
  "title": "…",
  "author": "…",
  "chapters": [
    {"id": "c1", "title": "Chapter 1", "paragraphs": [
      {"id": "c1.p1", "sentences": [{"id": "c1.p1.s1", "text": "…"}]}
    ]}
  ],
  "pages": [
    {"number": 1, "chapterId": "c1", "words": 297, "sentenceIds": ["c1.p1.s1", "…"]}
  ]
}
```

Идентификаторы — порядковые номера глав, абзацев и предложений, поэтому
повторная обработка того же текста даёт те же id. `bookId` считается по названию,
автору и тексту глав, а не по файлу: переименование EPUB его не меняет.

### Отображение в Mini App

Оба формата читаются из структуры `chapters`. Поле `pages` старого конвертера
не определяет экранные страницы. Браузер раскладывает текущую главу в CSS-колонки
по ширине и доступной высоте экрана; свайп влево открывает следующую страницу,
вправо — предыдущую. На границе главы свайп переходит в соседнюю главу.
Вертикальной прокрутки текста нет. Счётчик внизу относится к текущей главе,
а не к печатному изданию и не ко всей книге.

В DOM сохраняются абзацы (`data-paragraph-id`), предложения (`data-sentence-id`)
и слова формата 2 (`data-word-id`, `data-word-key`). Пробелы и пунктуация между
словами берутся из исходного текста; повторного разбора языка на телефоне нет.
Предложение может продолжаться на следующей странице; полный контекст остаётся
в загруженном JSON. Заголовок из абзацев не дублируется из `chapter.title`.

При изменении размеров используется адрес видимого текста — ID предложения
и смещение, дополнительно ID слова, — чтобы открыть страницу с тем же местом.
Учитываются стабильная высота Telegram и безопасные отступы. Между запусками
позиция пока не сохраняется; definitions пока не подключены.

Перед показом читалка проверяет структуру файла, диапазоны слов, уникальность ID
и соответствие `bookId` записи каталога. Код этого этапа добавлен без запуска
тестов и браузера по просьбе пользователя; проверка на телефоне остаётся за ним.

## 2. Расположение файлов в Storage

Используется общий приватный bucket приложения: `SUPABASE_BUCKET=Umbrello`.
Название учитывает регистр; отдельной переменной или bucket для Books нет.

```text
Umbrello/
└── books/
    ├── index.json           ← каталог
    ├── my-book/
    │   └── book.json
    └── another-book.json    ← допустим и файл прямо в books/
```

Путь книги должен соответствовать шаблону
`books/<имя>.json` или `books/<папка>/<имя>.json`, где имя и папка состоят из
строчных латинских букв, цифр и дефиса (до 64 символов). Других уровней
вложенности, заглавных букв и `..` нет. Worker отдаёт только файлы, перечисленные
в каталоге; запрос по произвольному пути невозможен.

## 3. Формат каталога books/index.json

```json
{
  "formatVersion": 1,
  "books": [
    {
      "bookId": "0f1e2d3c4b5a69788796a5b4c3d2e1f00f1e2d3c4b5a69788796a5b4c3d2e1f0",
      "title": "My Book",
      "author": "Author Name",
      "path": "books/my-book/book.json"
    }
  ]
}
```

Правила (иначе Worker отвечает `books_catalog_invalid`):

| Поле | Требование |
| --- | --- |
| `formatVersion` | Число `1`. |
| `books` | Массив, до 500 книг. Пустой массив — пустая библиотека. |
| `bookId` | Ровно `bookId` из `book.json`: 64 символа `0-9a-f`, без повторов. |
| `title` | Непустая строка до 300 символов (обычно `title` из `book.json`). |
| `author` | Строка до 300 символов или `null`. Поле обязательно. |
| `path` | Путь внутри bucket по шаблону из раздела 2, без повторов, не `books/index.json`. |

Порядок книг в массиве — порядок в библиотеке. Браузер получает только
`bookId`, `title` и `author`; пути остаются на сервере. Каталог — до 256 КиБ,
книга — до 8 МиБ.

## 4. Настройки Worker

Код — `worker/cf_worker.js`. В **Settings → Variables and Secrets** существующего
Worker нужны:

| Имя | Тип | Значение |
| --- | --- | --- |
| `ALLOWED_USER_IDS` | Variable | Общий список числовых Telegram ID через запятую, например `111111111,222222222` |
| `SUPABASE_BUCKET` | Variable | `Umbrello` — общий приватный bucket приложения |
| `SUPABASE_URL` | Variable | Существующий URL проекта: `https://<project-ref>.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Secret | Существующий ключ `sb_secret_…` или legacy service-role JWT |
| `BOT_TOKEN` | Secret | Уже есть; нужен для проверки подписи Telegram |

Существующий флаг совместимости `cache_option_enabled` оставь включённым.
`BOT_TOKEN`, `CHAT_ID` и настройки OpenAI сохраняются. Общий список доступа
используется всеми POST-маршрутами Worker, в том числе Write и отчётами.
Ключ Supabase остаётся только в секретах Worker: в браузер не попадают ни ключ,
ни ссылки на Storage. Переименование старых переменных — в [WORKER.md](WORKER.md).

Пустой или некорректный `ALLOWED_USER_IDS` закрывает Books для всех
(`books_not_configured`). Аккаунт не из списка получает `books_forbidden`.
Обычно отказ виден раньше: общий экран входа получает `app_forbidden` или
`app_not_configured` и показывает анимацию зонтика, а владельцу отправляется
уведомление с именем, @username и ID. Прямые запросы Books тоже защищены:
на `books_forbidden`, `books_not_configured` и `unauthorized` страница
блокируется тем же зонтиком. ID на экране не показывается нигде.

## 5. Загрузка книги и публикация — по шагам

1. **Подготовь книгу** в `tools/book-preparer.html` (раздел 1), скачай JSON
   и запиши `bookId` из него. Сохрани файл в `output/my-book/book.json`.
2. **Составь каталог** локально, например `output/index.json` (папка
   не попадает в Git). Добавь запись книги по формату из раздела 3; при
   следующей книге дополняй тот же файл, сохраняя прежние записи.
3. **Загрузи книгу.** Supabase → **Storage** → приватный bucket `Umbrello`.
   Создай папку `books`, внутри — `my-book`, и загрузи туда
   `output/my-book/book.json`. Итоговый ключ: `books/my-book/book.json`.
   `preview.html` и EPUB не загружай. Bucket должен оставаться не Public.
4. **Загрузи каталог** в `books/` под именем `index.json`. Если файл уже есть,
   удали старый `books/index.json` (или выбери замену, если панель её
   предлагает) и загрузи новый. Название файла должно быть ровно `index.json`.
5. **Обнови Worker:** вставь код из `worker/cf_worker.js`, настрой общие
   `ALLOWED_USER_IDS` и `SUPABASE_BUCKET` по [WORKER.md](WORKER.md) и нажми **Deploy**.
   После перехода на эти настройки новые книги не требуют повторного деплоя
   Worker: он передаёт файл книги без изменения. Версия каталога остаётся `1`.
6. **Опубликуй сайт** привычным способом (GitHub Pages). Нужны файлы:
   `books.html`, `read.html`, `index.html`, `assets/js/books.js`,
   `assets/js/books-core.js`, `assets/js/books-reader.js`, `assets/js/read-tabs.js`,
   `assets/js/home.js`, `assets/js/profiles.js`, `assets/css/style.css`, `assets/css/books.css`.
   Для общего экрана входа публикуются также остальные обновлённые HTML-страницы.
   Не публикуй локальные книги: `output/`, `*.epub` и JSON с текстом.
7. **Узнай Telegram ID.** Закрой и снова открой Mini App из Telegram.
   Если доступа нет, появится анимация зонтика без текста, а имя, @username
   и ID придут владельцу в чат бота.
8. **Разреши доступ:** добавь нужные ID в `ALLOWED_USER_IDS` через запятую
   и сохрани настройки Worker. Закрой и снова открой Mini App, затем **Read → Books**.
9. **Проверь вживую:** открой Books с обоих аккаунтов — книга видна, страницы
   листаются свайпом, длинное предложение продолжается на следующем экране,
   после поворота сохраняется место. Аккаунт не из списка видит только зонтик. В обычном браузере без Telegram книги не загружаются.
   Grammar и Learn words работают как раньше.

Новая книга позже: шаги 1–4 и 9 (Worker и сайт трогать не нужно).
Если Telegram показывает старую версию страниц, перезапусти мини‑приложение;
номера `?v=` у изменённых файлов уже обновлены.

### Текущий файл The Woman in the Dunes

Локальный файл `1- The Woman in the Dunes.json` подготовлен в формате 2:
61 137 слов, 39 разделов, около 3,4 МиБ. Он исключён из Git. Для него можно
использовать следующую запись внутри массива `books` в каталоге:

```json
{
  "bookId": "98ad3e51e0f0fb0c43425d44d9e75a570478e7f15a7dd6299e9176984a86f0df",
  "title": "The Woman in the Dunes",
  "author": "Kobo Abe",
  "path": "books/the-woman-in-the-dunes/book.json"
}
```

Загрузи локальный файл под именем `book.json` по этому пути. Если заменяешь
прежнюю версию книги, обнови её запись в существующем каталоге, сохрани остальные
книги. `bookId` должен совпадать с новым JSON; имя файла на компьютере не важно.
Весь каталог не нужно переводить в формат 2: его `formatVersion` остаётся `1`.

## API

Все маршруты — `POST` JSON с `initData`; ответы с `Cache-Control: no-store`.

| Маршрут | Дополнительные поля | Успешный ответ |
| --- | --- | --- |
| `/books/list` | — | `{"books": [{"bookId", "title", "author"}]}` |
| `/books/book` | `bookId` (64 hex) | `book.json` из пути, указанного в каталоге |

## Ошибки

| Код | Что проверить |
| --- | --- |
| `unauthorized` | Открой приложение заново из Telegram: подпись неверна или старше 24 часов. |
| `books_not_configured` | С ID: не задан или некорректен `ALLOWED_USER_IDS`. Без ID: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` или `SUPABASE_BUCKET`. |
| `books_forbidden` | Подписанный ID не в `ALLOWED_USER_IDS`. |
| `books_not_found` | Нет `books/index.json` или файла книги по пути из каталога; книги нет в каталоге. |
| `books_catalog_invalid` | Формат `books/index.json` (раздел 3). |
| `books_storage_auth` | Секретный ключ и доступ к приватному bucket. |
| `books_storage_size` | Каталог больше 256 КиБ или книга больше 8 МиБ. |
| `books_storage_network` / `_timeout` / `_error` / `_read` / `_empty` | Доступность Supabase и загруженные файлы. |
| `books_runtime_cache` | Включи `cache_option_enabled` в compatibility flags Worker. |
| `invalid_input` | Неверный `bookId` в запросе. |
| «The book file is invalid (…)» | Загружен не тот или повреждённый `book.json`, либо `bookId` в каталоге не совпадает с файлом. |

## Существующие проверки

```sh
node --test tests/*.test.cjs
uv run --project tools python -m unittest tests/prepare_book_test.py
```

Автотесты покрывают формат каталога и книги, разбиение на страницы и Worker.
Читалку в Telegram, настоящие Supabase и Worker они не подтверждают — для этого
нужен шаг 9.
