# Vocabulary: уровни, юнит за юнитом

Общий раздел: открыт всем разрешённым аккаунтам с главного экрана, профиль
не нужен. Каждый уровень — одна книга серии English Vocabulary in Use,
юнит за юнитом. Сейчас уровни Elementary (A1–A2) и Upper-intermediate (B2).
Каждый юнит самостоятельный, связей с другими разделами нет. Минимальный
прогресс сохраняется на устройстве (см. «Прогресс на устройстве»).

## Как устроен раздел

- `vocabulary.html` без параметров показывает список уровней из
  `vocabulary/index.json`: уровень, CEFR, книга, сколько юнитов готово и пройдено.
  Уровни идут в порядке списка — от лёгкого к сложному.
- `vocabulary.html?v=10&book=upper-intermediate` показывает оглавление уровня
  из `vocabulary/upper-intermediate/index.json`. Открываются только юниты,
  у которых указан `id`. Оглавление запрашивается, только если уровень есть в списке.
- `…&book=upper-intermediate&unit=unit-012` открывает юнит из
  `vocabulary/upper-intermediate/unit-012.json`. Файл юнита запрашивается,
  только если оглавление отмечает его готовым.
- Кнопка «Назад» Telegram ведёт из юнита к оглавлению уровня, из оглавления —
  к списку уровней, оттуда — в меню.

```text
vocabulary/
├── index.json                    ← уровни
├── elementary/
│   ├── index.json                ← оглавление книги уровня
│   └── unit-004.json …
└── upper-intermediate/
    ├── index.json
    ├── unit-006.json
    └── unit-012.json …
```

Юнит начинается с короткого описания: о чём он, части A, B, C и пять шагов.
Шаги открываются по очереди, следующий — только после предыдущего:

1. **Warm-up** — фразы юнита по-украински, нужно угадать английский вариант
   до объяснений. После ответа сразу виден правильный. Есть «I don't know».
2. **Learn** — части юнита одна за другой. У каждой фразы шаблон, значение,
   пример с озвучкой, ещё примеры, перевод под размытием и «Watch out» —
   ловушки для русско- и украиноязычных. После каждой части три вопроса
   с выбором ответа. Часть без фраз (таблица «One word, two jobs») — справка.
3. **Practice** — как в Полиглоте: предложение с пропуском и 6 вариантов.
   Рейтинг — 5 × доля правильных среди последних 20 ответов. Story открывается
   на 4.5, то есть 18 правильных из последних 20. Ошибка возвращается через
   4–7 других вопросов. Когда вопросы заканчиваются, колода перемешивается заново.
4. **Story** — Worker просит модель написать короткую историю на случайную
   тему юнита: на английском, с фразами юнита, и её перевод на украинский.
   Пользователь видит украинский текст и список фраз, пишет свой английский
   вариант и жмёт **Done**. Второго запроса нет: сразу показывается английская
   версия из того же ответа с подчёркнутыми фразами. **Another story** —
   новая тема. Если запрос не удался, можно взять пример из файла юнита.
5. **Final mix** — каждая фраза ещё раз в новом предложении, ответ печатается,
   даны первые буквы. Регистр, апострофы и точка в конце не важны; одна опечатка
   в слове от 5 букв засчитывается как «почти». Ошибки возвращаются один раз в конце.

В конце — сводка: Warm-up, рейтинг Practice, Story, Final mix.

## Прогресс на устройстве

Как в Books: `localStorage`, отдельно для каждого Telegram-аккаунта, подтверждённого
Worker, каждого уровня и юнита — ключ `umbrello.vocabulary.v1.<userId>.<level>.unit-NNN`.
На сервер ничего не уходит, на другом телефоне прогресса не будет.

Хранится только:
- `done` — пройденные шаги. Шаг открыт, когда пройдены все шаги перед ним;
- `scores` — результаты Warm-up и Final mix (`"7 / 8"`);
- `practice` — последние 20 ответов Practice и счётчики ✓/✗, чтобы рейтинг
  продолжался после закрытия приложения (очередь вопросов начинается заново);
- `finishedAt` — дата, когда юнит пройден впервые.

Текст истории, ответы внутри шагов и место в Learn не сохраняются: шаг,
прерванный на середине, начинается сначала. В оглавлении у юнита видно
**Open**, **Step N of 5** или **✓ Done**. На экране юнита есть
**Start the unit over** (нажать два раза): сбрасывает шаги и результаты,
отметка «Done» и дата остаются. Сохранённые данные проверяются
`VocabularyCore.progressOf`; всё непонятное отбрасывается.
Интерфейс на английском, переводы и пояснения — на украинском.

## Файл юнита

`vocabulary/<book>/unit-NNN.json`, проверяется `VocabularyCore.validateUnit`
(`assets/js/vocabulary-core.js`). Если что-то не так, страница показывает
«Could not load» и место, которое нужно исправить, например
`Check practice[3]: give one right and 5 different wrong answers.`

| Поле | Что в нём |
| --- | --- |
| `schemaVersion` | `1` |
| `number`, `title` | Номер и название юнита, как в `index.json` |
| `about` | Одно-два предложения: о чём юнит (экран перед стартом) |
| `parts` | Части: `id`, `title`; у части-справки ещё `note` и/или `table` (`columns`, `rows`) |
| `items` | Фразы: `id` (`a1`), `part`, `phrase`, `pattern`, `meaning`, `uk`, `example` с фразой в `**…**`; по желанию `more`, `watchOut`, `ipa` |
| `warmup` | `uk`, `q` с одним `___`, `right`, 2–4 `wrong`, `explain`, `item` |
| `checks` | По каждой части с фразами: вопросы в том же виде, без `uk` |
| `practice` | Не меньше 20: `q`, `right`, ровно 5 `wrong`, `item`. Каждая фраза — хотя бы один раз |
| `mix` | `q`, `answers` (все верные варианты), `item`. Каждая фраза — хотя бы один раз |
| `story` | `topics` — темы для истории; `example` — запасная история (`title`, `uk`, `en`) |

Разметка фраз в английской истории: `[[words used|id]]`, например
`[[had run out|a4]]`.

Ещё правила, которые проверяет валидатор:
- в `practice` нет одинаковых предложений, а предложение из `mix` не повторяет
  предложение из `practice`: Final mix проверяет фразу, а не память о вопросе;
- справочная часть (box вроде Language help или Common mistakes) — часть
  без фраз, с `note` и/или `table`; её `id` может быть любым (`H`, `M`).

Особые типы юнитов:
- **Словообразование** (суффиксы, приставки): фраза — это сам суффикс
  (`-ee`, `-able`), в `pattern` — что он делает и примеры слов. В Practice
  неправильные варианты — другие формы того же корня (employer / employment…).
  В Final mix в конце предложения стоит корень заглавными, например `(DRIVE)`:
  одной первой буквы мало. Корень в скобках и голый суффикс не озвучиваются.
- При вводе ответа дефис считается пробелом: `heat-wave` = `heat wave`.

Вопросы и примеры пишутся для приложения: фразы из книги, предложения свои.
Файлы юнитов публичные, как и остальные файлы GitHub Pages, поэтому текст
книги дословно сюда не кладём.

## Как добавить юнит

1. Положи `vocabulary/<book>/unit-NNN.json` (номер из трёх цифр).
2. В `vocabulary/<book>/index.json` добавь этому юниту `"id": "unit-NNN"`.
3. Запусти `node --test tests/vocabulary.test.cjs`: тест проверяет все книги
   и все юниты из их оглавлений.

Новый юнит не требует новой версии `?v=`: JSON загружается без кэша.

## Как добавить уровень

1. `id` уровня — строчные латинские буквы, цифры и дефисы, по названию уровня,
   например `pre-intermediate`.
2. Создай папку `vocabulary/<id>/` с `index.json` — оглавлением, в том же формате,
   что у Upper-intermediate: `book` (название с уровнем, оно же уходит в запрос
   истории) и `groups` с юнитами.
3. Добавь уровень в `vocabulary/index.json`: `id`, `level` (название уровня,
   оно же заголовок), `book` (название книги), по желанию `cefr` (`A2–B1`)
   и `about` — одна строка о содержании. Ставь его по сложности: список
   показывается в том же порядке.
4. Добавляй юниты, как описано выше.

Уровень важен для Story: Worker просит модель держать остальную лексику
и грамматику на уровне книги, а для Elementary и Pre-intermediate писать
историю короче (70–90 слов) и простыми предложениями.

## История через Worker

`POST /vocabulary/story` — `initData`, `book` (название и уровень книги, до 120
символов), `unit` (до 120), `topic` (до 200) и `phrases`: 5–60 фраз юнита
с `id`, `phrase`, `pattern`, `meaning`. Без `book` (страница старой версии)
Worker считает книгу Upper-intermediate.
Ответ: `{ "title", "uk", "en" }`.

- Запрос проходит ту же проверку Telegram-подписи и `ALLOWED_USER_IDS`, что Write.
- В OpenAI уходят только `book`, `unit`, `topic` и `phrases`. Ответ строится по JSON-схеме
  (`text.format`, `strict: true`), `store: false`.
- Worker проверяет ответ: украинский текст без английской разметки, в английском
  не меньше 5 размеченных фраз юнита. Метки с чужим `id` превращаются в обычный текст.
  Иначе — `invalid_response`.
- Коды ошибок те же, что у Write (`not_configured`, `rate_limit`, `timeout`…);
  страница показывает их по-английски с кодом в скобках.

## Проверки и публикация

```sh
node --test tests/vocabulary.test.cjs tests/vocabulary-worker.test.cjs
```

Тесты проверяют оглавление и все юниты, правило рейтинга, очередь ошибок,
проверку ввода, разметку истории и маршрут Worker (с подставными ответами модели).
Сам ход юнита в браузере тестами не покрыт.

Для историй нужны обе части: новый `worker/cf_worker.js` в Cloudflare и файлы
на GitHub Pages. После изменения `assets/js/vocabulary*.js` или
`assets/css/vocabulary.css` подними их `?v=` в `vocabulary.html`.
